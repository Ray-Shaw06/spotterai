# SpotterAI Release 2 Implementation Plan

Date: 2026-07-18
Design: `docs/superpowers/specs/2026-07-18-release-2-design.md`
Branch: `claude/release-2` from baseline `6a4d674`
Worklog: `docs/release-2-worklog.md`

Each task is a coherent, revertable commit with tests passing at its end.
Order matters: the report ships value before video; video builds on the
report's timeline data.

## Task 1 — Session timeline capture (pure module)

New `form-session.js`:

- `SessionRecorder` — `startedAt`, `exerciseId`; methods:
  - `recordRep({ tMs, rep, verdict })` — verdict is the existing
    `{ level, text }` depth feedback (or the low-confidence refusal).
  - `recordCues(tMs, cues)` — deduped per activation, not per frame:
    a warn cue is counted once per rep window, so "N of M reps" is honest.
  - `recordConfidence(conf)` — running stats.
  - `summary()` — pure output: reps, per-rep list, cue frequency
    `[{ text, level, reps: n }]`, best/worst rep indices, average
    confidence, judged-rep count.
- Tips: `tipsFor(summary, exercise)` — deterministic top-N mapping from
  most frequent warn cues to the exercise's existing cue text plus a
  brief actionable line; no free text generation.
- Wire into `form-coach.js`: recorder created on Start, fed in the loop
  (rep completion + cues + confidence), snapshot taken on Stop.
- Tests: `test/form-session.test.js` — frequency counting windows,
  best/worst pick, low-confidence sessions, zero-rep sessions, tip
  determinism.

## Task 2 — Post-session report UI

- `index.html`: report container inside the form-check page, hidden until
  a session ends with ≥1 rep.
- `form-coach.js` renders on stop: summary line, per-rep chip strip,
  cue frequency list with counts, tips, the honest-limitation line, and a
  "Start another set" affordance. Pain message keeps DOM priority.
- `style.css`: report styles in the product register — no new palette,
  44px touch targets, single-column at 390px.
- Tests: string-level rendering checks (given a summary, the produced
  markup contains the arithmetic truths) + `test/ui-layout.test.js`
  additions for the new selectors.

## Task 3 — Pull-up and dip evaluators

- `form-evaluator.js`:
  - `EXERCISES.pullup` — rep gate on elbow angle (down/hang ≈ open,
    up/top ≈ closed; metric "min" like curl inverted per existing grammar),
    chin-over-bar proxy: wrist y vs nose y at peak; swing/kipping cue from
    hip x-drift amplitude; setup text: camera front-on or 45°, full body.
  - `EXERCISES.dip` — elbow rep gate, depth to ~90°, excessive forward
    lean cue via torso angle.
  - Thresholds in the shared `T` table with the same tuning style.
- `index.html`: two new `<option>`s in the exercise select.
- Tests: `test/form-evaluator.test.js` pattern — synthetic angle
  sequences count reps; cue triggers fire at threshold violations;
  reliability gating respects the joints each metric uses.

## Task 4 — Local video recording + highlight scrubbing

- `form-coach.js`: on Start, attach `MediaRecorder` to the existing
  `getUserMedia` stream (no second capture). Chunks into memory;
  stop produces a Blob URL. Feature-detect `MediaRecorder` +
  `isTypeSupported`, preferring `video/mp4` (iOS Safari), falling back
  to `video/webm`. Any recorder error → session continues, report
  degrades to timeline-only.
- Report embeds `<video playsinline controls>` with the blob source and
  a marker strip: one marker per flagged rep + the best rep. Tap seeks
  to `repTimestamp - 1.5s`. Rep timestamps come from Task 1's timeline
  (`tMs` relative to recorder start).
- Object URL revoked and blob dropped on new session, route change, or
  pagehide (existing stop hooks).
- Size guard: recording hard-stops (video only, session continues) at a
  duration cap (10 min) to bound memory.
- Tests: pure helpers (marker building from summary + timestamps, mime
  selection order) unit-tested; the recorder itself is browser-only and
  covered by manual verification.

## Risks and honest gaps

- **iOS MediaRecorder**: supported since iOS 14.3 but codec quirks are
  real; mp4-first mitigates. Physical-device verification is owner-gated
  (no device in this workspace) — the degraded path must make this safe
  to ship regardless.
- **Pull-up camera angle**: pull-ups are usually filmed front-on, unlike
  the side-on lifts; the side-selector and torso-lean heuristics must not
  fire nonsense cues front-on. Mitigation: pull-up metrics use bilateral
  averages and skip torso-lean cues; confidence gate already refuses
  low-visibility judgment.
- **Memory**: a 10-minute 720p webm is roughly 50–150 MB in memory on
  some browsers. Duration cap + immediate revoke on discard bounds it;
  persistent storage is explicitly out of scope.
