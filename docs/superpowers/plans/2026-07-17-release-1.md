# SpotterAI Release 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish SpotterAI Release 1 with clear measurement inputs, first-workout activation, privacy-safe funnel analytics, recoverable AI failures, and account-free scheduled Web Push for installed iPhone and Android PWAs.

**Architecture:** Preserve the current static HTML/CSS/native-ES-module application and Vercel serverless API. Add small pure modules for measurements, analytics, AI failure classification, notification preferences, authentication, validation, and scheduling; keep Firebase notification documents server-only; dispatch Web Push from a Firebase scheduled function; extend the existing service worker for receipt and click routing.

**Tech Stack:** Native ES modules, HTML/CSS, Node 18+ tests and Vercel functions, `firebase-admin`, Firebase Cloud Functions v2, Firestore, `web-push`, Luxon, Vercel Web Analytics, existing PWA service worker.

## Global Constraints

- Work from a clean `codex/release-1` branch and isolated worktree based on production commit `1b94973`.
- Cherry-pick only the Release 1 documentation commits; never include the unrelated Paddington commits or `output/` directory.
- Do not migrate frameworks, hosting, Firebase sync, AI providers, or the Vercel deployment.
- Keep every consumer feature free and require no Google sign-in for notifications.
- Preserve the deterministic evaluator, repair flow, AI fallbacks, Firebase user sync, installability, offline shell, and all existing tests.
- Notification permission appears only after plan creation and a direct user action.
- Official notification targets are installed iPhone Home Screen PWAs and installed Android PWAs with standards-based Web Push.
- Default quiet hours are 22:00–08:00 local time; no device receives more than two notifications per local calendar day.
- Never store measurements, injuries, nutrition, plan/workout contents, photos, AI conversations, names, or emails in notification records.
- Never send health inputs, food descriptions/images, AI content, raw errors, account identifiers, or push data to analytics.
- Firebase Blaze billing, production secrets, Firebase deployment, Vercel production promotion, and other public actions remain explicit owner gates.
- Use test-driven development, one independent reviewer gate per task, focused commits, and evidence entries in `docs/release-1-worklog.md`.

## Locked file structure and interfaces

### Browser modules

- `measurements.js`: pure measurement normalization, validation, and bidirectional conversion.
- `analytics.js`: allow-listed, non-blocking funnel telemetry using manual Vercel pageviews.
- `ai-errors.js`: fetch timeout composition plus safe AI failure classification and user copy.
- `notifications.js`: pure schedule presets, preference normalization, and capability-independent validation.
- `notification-client.js`: service-worker subscription and authenticated notification API client.
- `notification-ui.js`: post-plan offer and Account controls; imports the pure/client modules.
- `reminders.js`: compatibility entry point that initializes the new notification UI; no legacy foreground-only reminder behavior.

### Vercel server modules

- `lib/firebase-admin.js`: lazy Firebase Admin initialization from server-only environment variables.
- `lib/notification-auth.js`: signed opaque bearer-token creation and verification using Node `crypto`.
- `lib/notification-validation.js`: strict API payload normalization and limits.
- `lib/notification-store.js`: Firestore adapter for server-managed `notificationDevices` documents.
- `api/notifications.js`: same-origin configuration/register/update/delete endpoint with dependency-injected handler for tests.

### Firebase dispatcher

- `functions/index.js`: exports the v2 scheduled function only.
- `functions/notification-schedule.js`: pure due-time, quiet-hours, daily-cap, category, payload, and next-event calculations.
- `functions/dispatcher.js`: Firestore lease/claim/send/finalize orchestration and expired-endpoint cleanup.
- `functions/package.json`: isolated function runtime dependencies.
- `firebase.json`, `firestore.rules`, `firestore.indexes.json`: deployment and server-only collection configuration.

- [ ] **Step 3: Implement the pure measurement module**

Use these exact constants and conversion rules:

```js
const KG_TO_LB = 2.2046226218;
const CM_PER_IN = 2.54;
const round1 = (n) => Math.round(n * 10) / 10;
const present = (v) => String(v ?? "").trim() !== "";

export const measurementSystem = (data = {}) => data.units === "lb" ? "imperial" : "metric";

export function switchMeasurementSystem(data = {}, target = "metric") {
  const next = { ...data };
  if (target === "imperial") {
    if (measurementSystem(data) === "metric" && present(data.height)) {
      const totalInches = Math.round(Number(data.height) / CM_PER_IN);
      next.heightFt = String(Math.floor(totalInches / 12));
      next.heightIn = String(totalInches % 12);
    }
    if (measurementSystem(data) === "metric" && present(data.weight)) next.weight = String(round1(Number(data.weight) * KG_TO_LB));
    next.units = "lb";
    return next;
  }
  if (measurementSystem(data) === "imperial" && (present(data.heightFt) || present(data.heightIn))) {
    next.height = String(Math.round(((Number(data.heightFt) || 0) * 12 + (Number(data.heightIn) || 0)) * CM_PER_IN));
  }
  if (measurementSystem(data) === "imperial" && present(data.weight)) next.weight = String(round1(Number(data.weight) / KG_TO_LB));
  next.units = "kg";
  return next;
}

export function validateMeasurements(data = {}) {
  const errors = {};
  if (measurementSystem(data) === "metric") {
    if (present(data.height) && !(Number(data.height) >= 100 && Number(data.height) <= 250)) errors.height = "Enter a height from 100 to 250 cm.";
    if (present(data.weight) && !(Number(data.weight) >= 30 && Number(data.weight) <= 350)) errors.weight = "Enter a weight from 30 to 350 kg.";
  } else {
    if (present(data.heightIn) && !(Number(data.heightIn) >= 0 && Number(data.heightIn) <= 11)) errors.heightIn = "Inches must be from 0 to 11.";
    const total = (Number(data.heightFt) || 0) * 12 + (Number(data.heightIn) || 0);
    if ((present(data.heightFt) || present(data.heightIn)) && !(total >= 39 && total <= 98)) errors.heightFt = "Enter a height from 3 ft 3 in to 8 ft 2 in.";
    if (present(data.weight) && !(Number(data.weight) >= 66 && Number(data.weight) <= 772)) errors.weight = "Enter a weight from 66 to 772 lb.";
  }
  return { valid: Object.keys(errors).length === 0, errors };
}

export function bodyweightKg(data = {}) {
  if (!present(data.weight)) return null;
  const value = Number(data.weight);
  if (!Number.isFinite(value) || value <= 0) return null;
  return measurementSystem(data) === "imperial" ? value / KG_TO_LB : value;
}
```

- [ ] **Step 3: Implement the allow-listed Vercel pageview helper**

```js
export const FUNNEL_EVENTS = Object.freeze({
  landing_cta_clicked: { source: ["hero", "final", "today"] },
  onboarding_started: { source: ["landing", "today", "plan"] },
  onboarding_completed: {},
  plan_generation_succeeded: { fallback_used: ["true", "false"] },
  plan_generation_failed: { failure_class: ["offline", "timeout", "rate_limited", "unavailable", "invalid_response", "unknown"] },
  plan_fallback_shown: { failure_class: ["offline", "timeout", "rate_limited", "unavailable", "invalid_response", "unknown"] },
  first_workout_started: { source: ["plan", "today", "dashboard"] },
  first_workout_completed: { source: ["plan", "today", "dashboard", "unknown"] },
  meal_photo_succeeded: {},
  meal_photo_failed: { failure_class: ["offline", "timeout", "rate_limited", "unavailable", "invalid_response", "unknown"] },
  notification_offer_shown: { platform_group: ["ios_pwa", "android_pwa", "unsupported"] },
  notification_prompted: { platform_group: ["ios_pwa", "android_pwa"] },
  notification_allowed: { platform_group: ["ios_pwa", "android_pwa"] },
  notification_denied: { platform_group: ["ios_pwa", "android_pwa"] },
  notification_opened: { notification_category: ["workout", "follow_up", "streak", "recovery"] },
});

export function trackFunnel(name, properties = {}) {
  const schema = FUNNEL_EVENTS[name];
  if (!schema) return false;
  const segments = [];
  const routeSegments = [];
  for (const [key, allowed] of Object.entries(schema)) {
    const value = String(properties[key] ?? "");
    if (!allowed.includes(value)) continue;
    routeSegments.push(`[${key}]`);
    segments.push(value);
  }
  const route = ["", "funnel", name, ...routeSegments].join("/");
  const path = ["", "funnel", name, ...segments].join("/");
  try { window.va?.("pageview", { route, path }); } catch {}
  return true;
}
```
